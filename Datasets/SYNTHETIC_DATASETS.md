# Synthetic Datasets

oneFCM uses synthetic workloads for scalability, stress, and local-memory
experiments. The corresponding generators are included in this directory so
that researchers can create the same workload types using the problem sizes
and generation procedures used in the study.

The data-generation seeds described here are separate from the oneFCM
membership-initialization seed selected with the `--seed` command-line option.

## Overview

| Workload | N | D | Clusters / modes | Generation | Data-generation seed |
| --- | ---: | ---: | ---: | --- | --- |
| Scalability n1e5 | 100,000 | 4 | 4 clusters | Two independent uniform 2D disks | Not fixed |
| Scalability n1e6 | 1,000,000 | 4 | 4 clusters | Two independent uniform 2D disks | Not fixed |
| Scalability n1e7 | 10,000,000 | 4 | 4 clusters | Two independent uniform 2D disks | Not fixed |
| Scalability n1e8 | 100,000,000 | 4 | 4 clusters | Two independent uniform 2D disks | Not fixed |
| Stress | 10,000,000 | 32 | 32 clusters | Uniform centers with Gaussian perturbations | Not fixed |
| Local-memory boundary | 40,960 | 393 | 512 modes | Deterministic prototype construction | 550 |

## Experimental input datasets

The archived numerical realizations used as inputs for the paper's reported
scalability and stress results are available from [Google Drive](https://drive.google.com/drive/folders/1khKdbfJknnbTpyhB4G-S2RRR0Y3uy3HU?usp=sharing).
The folder contains these five feature CSV files:

- `scalability_n1e5.csv`
- `scalability_n1e6.csv`
- `scalability_n1e7.csv`
- `scalability_n1e8.csv`
- `stress_test_n1e7_d32_k32.csv`

The released generators document the corresponding workload construction and
parameters. The scalability and stress generators do not set a data-generation
seed, so running them produces new numerical realizations that follow the same
workload definitions but are not expected to reproduce the archived coordinates
exactly.

## Scalability datasets

The scalability study uses four datasets with `D = 4` and four generating
clusters. The generator cluster count and the runtime setting `K = 4` have the
same value for these experiments.

### Generation

Each four-dimensional point is formed from two independent samples drawn
uniformly from two-dimensional disks of radius `R = 9`. For cluster `i`, the
first coordinate pair is generated by:

```text
alpha1 ~ Uniform(0, 2*pi)
u1     ~ Uniform(0, 1)
r1      = 9 * sqrt(u1)
x1      = C[i,1] + r1 * cos(alpha1)
x2      = C[i,2] + r1 * sin(alpha1)
```

New independent draws `alpha2`, `u2`, and `r2 = 9 * sqrt(u2)` generate `x3`
and `x4` around the second coordinate pair of the same center. The resulting
four-dimensional distribution is the product of two independent uniform 2D
disks.

The fixed centers are:

```text
C0 = (40, 40, 60, 60)
C1 = (40, 60, 60, 40)
C2 = (60, 40, 40, 60)
C3 = (60, 60, 40, 40)
```

### Parameters

| Dataset | Generator | N | Points per cluster |
| --- | --- | ---: | ---: |
| n1e5 | `generate_scalability_n1e5.py` | 100,000 | 25,000 |
| n1e6 | `generate_scalability_n1e6.py` | 1,000,000 | 250,000 |
| n1e7 | `generate_scalability_n1e7.py` | 10,000,000 | 2,500,000 |
| n1e8 | `generate_scalability_n1e8.py` | 100,000,000 | 25,000,000 |

Coordinates are stored as `numpy.float32`. Points are written in cluster-major
order without shuffling, and the source-cluster labels are `0` through `3`.
Each feature CSV has the header `dim1,dim2,dim3,dim4`.

The generators use Python's global `random` module and do not set an explicit
random seed. Individual generated coordinates may therefore differ between
runs while following the same distribution and parameters.

### Recreating the datasets

Run the script for the required size from the scalability directory. For
example:

```bash
cd Datasets/scalability
python3 generate_scalability_n1e5.py
```

The required Python packages are listed in [`README.md`](README.md).

## Stress dataset

The stress workload fixes `N`, `D`, `K`, the data representation, and the
generation distribution to create a high-computation, high-contention FCM
configuration.

### Generation

For each cluster `k` and dimension `j`, the center coordinate is sampled
independently using NumPy's `U[0,100)` distribution:

```text
C[k,j] ~ Uniform(0, 100)
```

Each point is generated by adding independent Gaussian perturbations to its
cluster center:

```text
X[k,p,j] = C[k,j] + epsilon[k,p,j]
epsilon[k,p,j] ~ Normal(0, 3.0^2)
```

The generator stores `cluster_std = 9.0`, but scales the standard-normal draws
by `cluster_std / 3`, giving an actual standard deviation of `3.0` and a
variance of `9.0`.

### Parameters

```text
N = 10,000,000
D = 32
K = 32
points per cluster = 312,500
```

The feature matrix uses `numpy.float32`, and source-cluster labels use
`numpy.int32`. Points are written in cluster-major order without shuffling;
the source labels are `0` through `31`.

The feature output is `stress_test_n1e7_d32_k32.csv`, with header
`dim1,...,dim32`, comma delimiters, and `%.4f` serialization. Source-cluster
labels are written separately to `stress_test_labels.txt`.

The generator uses NumPy's global `np.random` state and does not set an
explicit random seed. Each execution may therefore produce different
coordinates while retaining the same problem size and distribution.

### Recreating the dataset

```bash
cd Datasets/stress
python3 generate_stress_test.py
```

This generator requires Python 3 and NumPy.

## Local-memory-boundary dataset

This deterministic dataset provides a 393-dimensional master input for the
local-memory-boundary experiments.

### Generation

The generator uses `DATA_SEED = 550` and a SplitMix64-style hash-based
construction to produce 256 base prototypes, their sign-mirrored modes, and 80
replicas per prototype. This gives 512 signed modes and `512 * 80 = 40,960`
points.

For each coordinate, the prototype and replica perturbation are combined as:

```text
numerator = sign * (prototype_odd * 256 + noise_odd)
x = numerator / 2048
```

`prototype_odd` is selected from `{-63, -61, ..., 61, 63}`. Replica `0` uses
`noise_odd = 0`; the remaining replicas select `noise_odd` from
`{-15, -13, ..., 13, 15}`. The detailed integer-mixing implementation is in
[`generate_local_memory_boundary.py`](local_memory_boundary/generate_local_memory_boundary.py).

### Parameters

```text
N = 40,960
D = 393
DATA_SEED = 550
PROTOTYPE_COUNT = 512
BASE_PROTOTYPE_COUNT = 256
REPLICAS_PER_PROTOTYPE = 80
```

Rows are written replica-major with header `f0,...,f392`, and coordinates use
11 fractional decimal digits. The fixed seed and deterministic construction
produce the same dataset when the released generator and parameters are used.

### Recreating the dataset

```bash
cd Datasets/local_memory_boundary
python3 generate_local_memory_boundary.py --output-dir <directory>
```

This generator uses only the Python 3 standard library.
